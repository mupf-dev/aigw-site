Docs

Condensed public editions of ai-gw's concept documents and operations handbook. The full documents (German) live in the repository under docs/.

Concepts 4 Pages

  • MCP gatewayai-gw as an MCP server for clients and as an MCP client to connected servers – with grants per team and key down to the tool level, credentials, limits, logging and SSRF protection.
  • Tool inventory and tool policiesai-gw records every tool that applications send along in model requests, detects changed or suspicious descriptions and enforces policies – from removing individual tools to approval on a case-by-case basis.
  • WASM pluginsCustom plugin logic as a WebAssembly component – in a sandbox inside the gateway process, with limits for CPU, time and memory, hot reload and optional mandatory Ed25519 signatures.
  • Workload and agent identitiesAI agents and services sign in with signed access tokens – primarily from Microsoft Entra Agent ID – instead of a distributed gateway key. The token acts exactly like the key to which the identity is mapped.

Operations and measurements 2 Pages

  • Performance and load comparisonTest setup and results of the latency and load tests of ai-gw, plus a comparison with the LiteLLM proxy under identical conditions – with method, raw values and the limits of what the results show.
  • Operations and hardeningRecommendations for operating ai-gw – network and listeners, secrets, data storage and multiple instances, admin access, data plane, plugins, monitoring and audit.

ai-gw (AI-Gateway) – Open-source, self-hosted AI gateway in Rust – one endpoint for many AI providers. One binary for gateway, admin API and admin UI.
