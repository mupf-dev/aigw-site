One endpoint.
Every model.

ai-gw is a self-hosted AI gateway: applications and agents speak an OpenAI- or Anthropic-compatible API, and ai-gw routes the requests to OpenAI, Azure OpenAI, Anthropic, AWS Bedrock, Gemini, Mistral, Ollama, vLLM and more – with keys per team, limits, budgets, guardrails and a complete request log. Gateway, admin API and admin UI ship as one binary.

Features

Everything that belongs between application and model.

Using AI models across several teams calls for key management, cost control, resilience, protection against data leakage and traceability. ai-gw brings this together in one place – in your own network and under your own control.

  • One format, many providers

    OpenAI- and Anthropic-compatible endpoints for chat, responses, embeddings, images and audio. Translation through a shared intermediate representation – including tools, vision and streaming.

  • Routing and resilience

    Model groups with aliases, weighted distribution, least latency or least busy, priorities (e.g. reserved capacity first), retries, fallback chains and circuit breakers.

  • Tenants, limits, budgets

    Organizations, teams and virtual API keys with model access, request and token limits, budgets with alert thresholds and costs per model, team and key.

  • Guardrails

    PII detection and masking, prompt-injection heuristics, word and regex rules, canary tokens against system-prompt leaks, link protection, language filters and external content safety.

  • MCP gateway and tool policies

    MCP servers behind one endpoint, grants per team and key down to individual tools, an inventory of all tools that applications send along, and policies against risky tools.

  • Agent identities

    AI agents sign in with signed access tokens, for example from Microsoft Entra Agent ID – no gateway key to distribute. The same rules apply as for the mapped key.

  • Response cache

    Exact cache in memory or Redis, semantic cache with a built-in HNSW index, pgvector or Redis Search – always partitioned per team.

  • Observability and GitOps

    Request log with costs, Prometheus metrics, OpenTelemetry traces, an audit log with hash chain and declarative YAML configuration with diff and dry run.

Admin-UI

Traffic, cost and health at a glance.

The admin UI is embedded in the binary. It shows requests, tokens, cost, latency, errors and cache hits per team and model, manages models, keys, guardrails and MCP servers, and follows your system's light/dark setting.

  • Log explorer with fallback attempts, cache hits and cost per request
  • Playground on behalf of a key – with its limits and guardrails
  • Guardrail profiles (basic, strict, open) with a diff before applying
  • YAML import/export with dry run, OIDC sign-in, roles

How a request flows

Everything from memory – no database on the hot path.

Keys, grants, limits and plugin chains live in RAM as an immutable configuration snapshot. Changes take effect on all instances in under a second; if the database fails, the gateway keeps running with the last known state.

  1. Authenticate

    API key (stored only as a hash) or an agent's signed token. Result: organization, team, grants and limits.

  2. Check

    Model access and tool policies are applied, limits and budgets reserved; guardrails inspect and mask the prompt.

  3. Forward

    Cache hits answer immediately. Otherwise routing picks a deployment, translates to the provider format and streams back chunk by chunk.

  4. Account

    Usage settles the reservation, costs are recorded, and the log event goes to the batch writer without blocking.

Providers

Your credentials, your contracts.

ai-gw calls providers with the operator's stored credentials. Secrets are encrypted (AES-256-GCM) in the database or read from the environment and files.
