Contribute#

ai-gw is developed in the open; source code, concepts and operations handbook live in the repository github.com/mupf-dev/ai-gw. Especially welcome:

  • Experience reports and bug reports as issues – with version, startup configuration (without secrets) and, if possible, a reproducible example.
  • Providers and formats: quirks of individual providers, new model capabilities, interoperability with clients and SDKs, MCP clients.
  • Guardrails: false positives and negatives of PII detection and the injection heuristics, new detection rules, example plugins as WebAssembly components.
  • Operations: experience with Kubernetes, Postgres, Redis, OpenTelemetry and large installations; load measurements on other hardware.
  • Code in Rust for gateway and admin API, Svelte and TypeScript for the admin UI, documentation and translations.

Rules for contributions#

  • Green check pipeline: scripts/check.sh bundles formatting, lints without warnings, tests, cargo deny (licenses and security advisories of dependencies), comparison of the OpenAPI specification, type checks and build of the UI, and REUSE. CI runs the same checks on pull requests.
  • Changed the admin API? Regenerate the OpenAPI specification and the UI's TypeScript types and commit them.
  • Every file carries SPDX license information (REUSE compliant).
  • New dependencies only after checking license, maintenance status and benefit; the license overview THIRD-PARTY.md is generated by a script.
  • Concept before code: larger changes start with a section in docs/konzept/ – with rationale, security considerations and measurements where the hot path is affected.
  • Keep the changelog under “Unreleased” and mark incompatible changes explicitly.
sh# typical workflow
git clone https://github.com/mupf-dev/ai-gw.git && cd ai-gw
scripts/setup-tools.sh        # toolchain and check tools in pinned versions
scripts/check.sh              # all checks locally
scripts/runtime-smoke.sh      # build, start and check the release binary with UI

The AGPL ensures that improvements benefit the community even when modified versions are offered as a network service – the typical case for a gateway. The repository is REUSE compliant; the licenses of dependencies are listed in THIRD-PARTY.md and checked against an allowlist with cargo deny. Attribution: “ai-gw contributors”.

Report a vulnerability#

Please do not use public issues, pull requests or discussions for security problems. Report them confidentially by e-mail to the address given in the legal notice – with a description, the affected version or commit and, if possible, a proof of concept. A confidential reporting channel on GitHub and a security policy in the repository will follow with the first release.

The usual rules of coordinated disclosure apply: receipt is acknowledged, the issue is assessed jointly, fixed and then published with credit to the reporter, if desired.
